# 🤝 BASIRAH — Contributing Guidelines

> Clean code. Clear communication. Strong teamwork.

---

## ✨ Overview

These guidelines help keep the BASIRAH project **organized, readable, and professional**.  
Please follow them carefully to ensure smooth collaboration and high-quality output.

---

## ✨ Best Practices

### 📚 **Documentation**
- **Always** include clear comments for complex logic.
- Use standard **docstrings** for functions to explain:
  - Parameters  
  - Return values  

### 🏷️ **Meaningful Naming**
- Use descriptive and readable names for variables, functions, and classes.
- Prefer clarity over brevity.
- Example:
  - ✅ **`calculate_total_price`**
  - ❌ **`calc_tp`**

### 🧩 **Keep It Simple (KISS)**
- Aim for simple, modular code.
- If a function becomes too long or complex:
  - Break it into smaller, testable units.

### 👀 **Readability**
- Follow consistent indentation and formatting rules.
- Code should be easy to understand at a glance.

---

## 🛠️ Development Rules

### 🔹 **Atomic Commits**
- Each commit should focus on **one change only**.
- Small commits make reviews and debugging easier.

### 📝 **Descriptive Commit Messages**
- Use the **imperative mood** and keep messages concise.
- Example:
  - ✅ **`Fix: resolve login validation error`**
  - ❌ **`fixed stuff`**

### 🧪 **Test Before Pushing**
- Ensure your changes do **not** break existing features.
- Run all local tests before pushing.
- Add new tests for any new functionality.

### 🎯 **Single Responsibility Principle**
- Each class or function should have **one clear responsibility**.

---

## 🚀 Pull Request Process

1. Fork the repository and create a new branch for your feature or fix.
2. **Link Issues**
   - Reference related issues in the PR description.
   - Example: **`Closes #12`**
3. **Clean Code Check**
   - Remove all **`TODO`** comments.
   - Remove debug print/log statements.
   - Ensure code follows project formatting and naming standards.

---

## 📌 Contribution Scope

🔒 **Contributions are limited to BASIRAH team members only.**  
All submissions must follow the rules outlined above.
